## FRD - User Story 22: Kubernetes Manifests and K8s DNS Migration

**ID:** US-22  
**Scope:** Full stack K8s deployment on Kind + K8s DNS service resolution  
**Primary flow:** `kubectl apply -k infra/k8s/overlays/local` -> all Deployments ready  
**Status:** Ready for implementation

### 1) User Story
As a DevOps engineer, I want Kubernetes manifests so the full stack deploys on Kind with K8s DNS.

### 2) Business Rules
- Kustomize `base/` defines one `Deployment` and `Service` per module.
- `overlays/local/` uses Eureka for optional compatibility.
- `overlays/staging/` disables Eureka and uses K8s DNS URIs.
- All Feign clients resolve via `http://<service>.<namespace>.svc.cluster.local`.
- Config Server runs as a `Deployment` and is referenced by all services.
- No hardcoded secrets in manifests; use `SecretKeyRef` or external secrets.

### 3) Functional Requirements
Kustomize tree:
```
infra/k8s/
  base/
    kustomization.yaml
    namespace.yaml
    deployments/
      user-service.yaml
      catalog-service.yaml
      order-service.yaml
      inventory-service.yaml
      payment-service.yaml
      notification-service.yaml
      api-gateway.yaml
      config-server.yaml
      service-registry.yaml
    services/
      <same set>.yaml
    configmaps/
      spring-profiles.yaml
  overlays/
    local/
      kustomization.yaml   # patches for local + Eureka enabled
    staging/
      kustomization.yaml   # patches for K8s DNS + Eureka disabled
```

K8s DNS URI example in staging config:
```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: http://user-service.eshop-lite.svc.cluster.local:8081
          predicates:
            - Path=/users/**, /auth/**
```

Deployment template (minimal):
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: user-service
spec:
  replicas: 1
  template:
    spec:
      containers:
        - name: user-service
          image: ghcr.io/<org>/eshop-lite/user-service:latest
          ports:
            - containerPort: 8081
          readinessProbe:
            httpGet: { path: /actuator/health, port: 8081 }
          env:
            - name: SPRING_PROFILES_ACTIVE
              value: k8s
            - name: JWT_SECRET
              valueFrom:
                secretKeyRef: { name: eshop-secrets, key: jwt-secret }
```

### 4) Data/Security/Observability/NFR
- Secrets must not be committed to repo; use `k8s/base/secrets-template.yaml` as example only.
- Metrics endpoints remain reachable for Prometheus scraping within cluster.
- NFR: all Deployments must reach `Ready` state within 2 minutes on Kind.

### 5) Tech Lead Guidance
- Keep Docker Compose intact for non-K8s local dev.
- Add `application-k8s.yml` Spring profile per service disabling Eureka.
- Use `kustomize edit set image` in CD pipeline for image tag replacement.
- Test full stack on Kind before staging.
