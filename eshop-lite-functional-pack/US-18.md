## FRD - User Story 18: Observability Dashboards and Alerts

**ID:** US-18  
**Scope:** Metrics, logs, traces, and alerting baseline  
**Stack:** Prometheus, Grafana, Loki, Jaeger  
**Status:** Ready for implementation

### 1) User Story
As an operator, I want actionable dashboards and alerts so incidents are detected quickly.

### 2) Business Rules
- Critical flows must have visible SLI-style signals (latency, error rate, retries, DLQ backlog).
- Alerts must include enough context to triage quickly.
- Correlation IDs must connect metrics/logs/traces.
- Dashboard panels must map to known operational questions.

### 3) Functional Requirements
Minimum dashboard panels:
- API success/error rate by service
- p95 latency for read/write endpoints
- retry and circuit-breaker counts/states
- outbox backlog and publish failure rate
- compensation and reconciliation lag indicators

Alert examples:
- breaker-open > threshold window
- retry spike > baseline multiplier
- DLQ backlog > threshold
- 5xx error rate > threshold

### 4) Data/Security/Observability/NFR
- Logs must include: `traceId`, `requestId`, `orderId`/`paymentId` where applicable.
- Alert channels and routing are environment-specific.
- NFR: dashboards should refresh fast enough for active incident response.

### 5) Tech Lead Guidance
- Version-control dashboard JSON and alert rules.
- Add consistent metric naming conventions across services.
- Add runbook links in alert annotations.
- Validate end-to-end trace navigation from logs.

### 6) QA Matrix
