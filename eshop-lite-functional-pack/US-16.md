## FRD - User Story 16: Security Hardening and Access Controls

**ID:** US-16  
**Scope:** Gateway + all protected service routes  
**Primary routes:** `/users/**`, `/auth/**`, `/orders/**`, `/payments/**`, `/inventory/**`  
**Status:** Ready for implementation

### 1) User Story
As a platform, I want stronger auth and route controls so protected paths are consistently enforced.

### 2) Business Rules
- Protected routes must return `401` when token is missing/invalid.
- Role-protected routes must return `403` for insufficient privileges.
- Error payloads follow Problem Details shape consistently.
- Security headers and correlation headers are enforced/propagated.
- No route should be implicitly public unless documented.

### 3) Functional Requirements
Security policy matrix (minimum):
- `POST /auth/login`: public
- `POST /users`: public
- `GET /products/**`: public
- `POST /products`: ADMIN
- `POST /orders`, `GET /orders/{id}`: authenticated user
- `POST /payments/authorize`: internal/service auth
- `/inventory/**`: internal/service auth

Problem Details `401` example:
```json
{
  "type": "https://eshop-lite/errors/auth",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Missing or invalid token",
  "traceId": "a1b2c3",
  "errors": []
}
```

Problem Details `403` example:
```json
{
  "type": "https://eshop-lite/errors/forbidden",
  "title": "Forbidden",
  "status": 403,
  "detail": "Insufficient privileges",
  "traceId": "a1b2c3",
  "errors": []
}
```

### 4) Data/Security/Observability/NFR
- Security config is externalized via config repo per environment.
- Token verification must be consistent at gateway and service layers.
- Metrics: `security_auth_failures_total`, `security_forbidden_total`.
- Logs include `traceId`, route, decision (`ALLOW`, `DENY`), reason.
- NFR: authorization decision latency should remain low (target p95 < 50ms service-side).

### 5) Tech Lead Guidance
- Create and maintain a single route-policy matrix doc/config source.
- Standardize exception handlers across services for `401/403` payloads.
- Add integration tests for authn/authz policy drift.
- Verify header propagation (`Authorization`, `X-Request-Id`, `traceparent`).

### 6) QA Matrix
- **US16-P1** valid token on protected path -> allowed.
- **US16-N1** missing token on protected path -> `401`.
- **US16-N2** invalid token -> `401`.
- **US16-N3** insufficient role -> `403`.
- **US16-O1** auth failures visible in metrics/logs/traces.
