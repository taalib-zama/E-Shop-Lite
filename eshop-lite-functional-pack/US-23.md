## FRD - User Story 23: Kubernetes Ingress and API Gateway Routing

**ID:** US-23  
**Scope:** Single-entry-point routing through K8s Ingress -> `api-gateway`  
**Primary flow:** External request -> Ingress -> api-gateway -> lb://service  
**Status:** Ready for implementation

### 1) User Story
As a DevOps engineer, I want a single Ingress entry point so only the gateway is exposed and all routes remain functional.

### 2) Business Rules
- Only `api-gateway` is exposed outside the cluster.
- All Sprint 1-4 Postman smoke routes must pass through the Ingress host.
- Sprint 4 `401/403` security behavior remains unchanged.
- TLS termination stub added for staging overlay.

### 3) Functional Requirements
Ingress manifest:
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: eshop-ingress
  namespace: eshop-lite
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: eshop-lite.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-gateway
                port:
                  number: 8080
```

TLS stub (staging overlay):
```yaml
spec:
  tls:
    - hosts:
        - eshop-lite.staging.fly.dev
      secretName: eshop-tls-secret
```

### 4) Data/Security/Observability/NFR
- No service other than `api-gateway` has an external `Service` of type `LoadBalancer` or `NodePort`.
- Gateway metrics remain reachable internally for Prometheus.
- NFR: Ingress routing adds `< 5ms` overhead locally.

### 5) Tech Lead Guidance
