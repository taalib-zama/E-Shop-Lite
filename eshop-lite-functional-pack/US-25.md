## FRD - User Story 25: Service Mesh Baseline - Linkerd mTLS and Traffic Policies

**ID:** US-25  
**Scope:** Linkerd injection on `eshop-lite` namespace  
**Primary flow:** Inject -> verify mTLS -> apply ServiceProfiles  
**Status:** Ready for implementation

### 1) User Story
As a DevOps engineer, I want a Linkerd mesh baseline so S2S calls are mTLS-protected and traffic policies are declarative.

### 2) Business Rules
- `linkerd check` must pass with zero errors.
- All S2S calls show 100% mTLS in `linkerd viz stat deploy`.
- `ServiceProfile` policies define retry/timeout per service pair.
- Linkerd supplements Resilience4j; it does not replace it.
- Injection is namespace-scoped, not pod-by-pod.

### 3) Functional Requirements
Namespace annotation:
```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: eshop-lite
  annotations:
    linkerd.io/inject: enabled
```

ServiceProfile example (order -> inventory):
```yaml
apiVersion: linkerd.io/v1alpha2
kind: ServiceProfile
metadata:
  name: inventory-service.eshop-lite.svc.cluster.local
  namespace: eshop-lite
spec:
  routes:
    - name: POST /inventory/reservations
      condition:
        method: POST
        pathRegex: /inventory/reservations
      isRetryable: true
      timeout: 1000ms
```

Verification commands:
```bash
linkerd check
linkerd viz stat deploy -n eshop-lite
linkerd viz tap deploy/order-service -n eshop-lite
```

### 4) Data/Security/Observability/NFR
- mTLS is transparent to application code.
- Linkerd Viz dashboard available at `http://localhost:50750`.
- `ServiceProfile` metrics visible in Linkerd Viz and Prometheus.
- NFR: Linkerd proxy adds `< 2ms` p99 overhead per hop on Kind.

### 5) Tech Lead Guidance
- Install Linkerd via CLI: `linkerd install | kubectl apply -f -`.
- Restart existing Deployments after namespace annotation to trigger injection.
- Keep `ServiceProfile` CRDs in `infra/k8s/base/serviceprofiles/`.
- Validate Resilience4j and Linkerd retry coexistence to avoid double retry amplification.

### 6) QA Matrix
- **US25-P1** `linkerd check` clean (`TC-S5-MESH-01`).
- **US25-P2** 100% mTLS stat verified (`TC-S5-MESH-02`).
- **US25-P3** ServiceProfile retry fires under injected latency (`TC-S5-MESH-03`).
- **US25-N1** Linkerd injection does not break existing health probes.

### 7) Validation Script
```bash
linkerd install --crds | kubectl apply -f -
linkerd install | kubectl apply -f -
linkerd check
kubectl annotate namespace eshop-lite linkerd.io/inject=enabled
kubectl rollout restart deployment -n eshop-lite
linkerd viz stat deploy -n eshop-lite
```

### 8) Architecture Alignment Note
Per `ARCHITECTURE.md` and `SYSTEM-DESIGN-ADDENDUM.md`:
- Kubernetes DNS replaces Eureka discovery in this overlay.
- Linkerd (or optionally Istio) adds mTLS and traffic policy without code changes.
- This is the stated upgrade path for E-Shop Lite from local to production-grade deployment.
