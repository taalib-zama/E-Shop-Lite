## FRD - User Story 12: Payment Failure Compensation

**ID:** US-12  
**Services:** `order-service` + `inventory-service` + `payment-service`  
**Flow:** `payment.failed.v1` -> compensation -> inventory release -> order cancel  
**Status:** Ready for implementation

### 1) User Story
As a platform, I want compensation when payment fails so order and inventory remain consistent.

### 2) Business Rules
- Payment failure triggers compensation workflow exactly once per order.
- Compensation releases reserved inventory.
- Order transitions to terminal `CANCELLED` state on completed compensation.
- Compensation operations are idempotent and retry-safe.
- Failures in compensation are retried through outbox/queue policy.

### 3) Functional Requirements
Primary trigger: `payment.failed.v1` event consumed by order workflow.

Optional internal endpoint for manual replay:
`POST /orders/{id}/compensate` (protected/admin-internal)

Success `200`:
```json
{
  "orderId": "2f5d5485-9180-4e1f-9a4f-74f43dc8c718",
  "status": "CANCELLED",
  "compensationStatus": "COMPLETED"
}
```

Problem Details example `409`:
```json
{
  "type": "https://eshop-lite/errors/compensation-conflict",
  "title": "Compensation already completed",
  "status": 409,
  "detail": "Order is already in terminal cancelled state",
  "traceId": "a1b2c3",
  "errors": []
}
```

### 4) Data Model
- Extend `orders` with compensation fields: `compensation_status`, `cancel_reason`.
- Optional table `compensation_actions(id, order_id, action_type, status, attempts, created_at, updated_at)`.
- Idempotency tracking for processed failure events.

### 5) Security, Observability, NFR
- Event consumer and internal replay endpoint are protected.
- Metrics: `order_compensation_requests_total`, `order_compensation_failures_total`, `order_compensation_duration_seconds`.
- Logs include `traceId`, `orderId`, `paymentId`, `compensationStatus`.
- p95 compensation completion target `< 2s` in local flow.

### 6) Tech Lead Guidance
- Implement compensation orchestrator in `order-service`.
- Add inventory release command/event invocation.
- Guard with idempotency key (`orderId + paymentEventId`).
- Mark workflow complete only after inventory release acknowledgment.
- Ensure retry/backoff via outbox dispatcher.

### 7) QA Matrix
- **US12-P1** payment failed event triggers cancel + release.
- **US12-P2** order status becomes `CANCELLED`.
- **US12-N1** duplicate failed event does not repeat side effects.
- **US12-N2** release temporary failure retries and recovers.
- **US12-O1** compensation metrics/logs/traces visible.
