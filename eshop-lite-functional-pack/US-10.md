
## FRD - User Story 10: Resilient S2S Failure Handling

**ID:** US-10  
**Service:** `order-service` with OpenFeign client to `inventory-service`  
**Route context:** `POST /orders` -> `ORDER-SERVICE` -> Feign call to `INVENTORY-SERVICE`  
**Status:** Ready

### 1) User Story
As a platform, I want resilient service-to-service calls so order flow handles dependency failures gracefully.

### 2) Business Rules
- Inventory calls use timeout, retry, and circuit breaker policies.
- Repeated failures open circuit and avoid cascading latency.
- On inventory dependency failure, order remains `PENDING_INVENTORY` (recoverable).
- Correlation/security headers are propagated end-to-end.

### 3) Functional Requirements
#### 3.1 S2S Behavior
- Feign client: `InventoryClient.reserve(...)`.
- Timeout budget example: connect `500ms`, read `1000ms`.
- Retry: small bounded retries with backoff.
- Circuit breaker: opens after configured failure threshold.
- Fallback: return control without hard-failing order create path.

#### 3.2 Failure Outcome Example
`POST /orders` may still return `201`:
```json
{
  "orderId": "2f5d5485-9180-4e1f-9a4f-74f43dc8c718",
  "status": "PENDING_INVENTORY",
  "recoveryHint": "Inventory reservation deferred"
}
```

### 4) Security and Header Propagation
Must propagate:
- `Authorization`
- `X-Request-Id`
- `traceparent`

### 5) Observability and NFR
- Metrics:
  - `resilience4j_retry_calls_total`
  - `resilience4j_circuitbreaker_state`
  - `inventory_client_calls_total{outcome="success|timeout|failure"}`
- Logs: include retry count, breaker state transitions, `traceId`.
- Tracing: spans show order-service -> inventory-service calls and fallback path.
- NFR target: no request thread exhaustion during downstream outage.

### 6) Tech Lead Guidance
- Add OpenFeign dependency and `@EnableFeignClients` to `order-service`.
- Create `InventoryClient` interface using service name `INVENTORY-SERVICE`.
- Add Feign `RequestInterceptor` for header propagation.
- Configure Resilience4j (`retry`, `circuitbreaker`, `timelimiter`) in config.
- Implement fallback handler that preserves recoverable order state.

### 7) QA Matrix
- **US10-P1** normal inventory response -> reserve path success.
- **US10-N1** inventory timeout triggers retry.
- **US10-N2** repeated failures open circuit breaker.
- **US10-N3** fallback returns recoverable order status.
- **US10-O1** retry and breaker metrics visible.
- **US10-O2** trace continuity includes fallback spans.

