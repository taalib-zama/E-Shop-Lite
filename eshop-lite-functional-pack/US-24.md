## FRD - User Story 24: CD Pipeline to Free Cloud Host

**ID:** US-24  
**Scope:** GitHub Actions CD pipeline -> Fly.io free staging  
**Primary flow:** merge to main -> build + tag -> deploy -> staging smoke  
**Status:** Ready for implementation

### 1) User Story
As a DevOps engineer, I want an automated CD pipeline so staging is updated on every main merge without manual steps.

### 2) Business Rules
- Pipeline triggers on merge to `main`.
- Images are built, tagged, and pushed to GHCR before deploy.
- Secrets sourced from GitHub Actions encrypted secrets only.
- Pipeline is idempotent on re-run.
- Staging smoke gate blocks further promotion on failure.

### 3) Functional Requirements
CD workflow (`cd.yml`) key stages:
```yaml
name: CD
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - name: Build and push all images
        run: |
          docker build -t ghcr.io/${{ github.repository_owner }}/eshop-lite/user-service:${{ github.sha }} -f services/user-service/Dockerfile .
          docker push ghcr.io/${{ github.repository_owner }}/eshop-lite/user-service:${{ github.sha }}
      - uses: superfly/flyctl-actions/setup-flyctl@master
      - name: Deploy to Fly.io
        run: flyctl deploy --image ghcr.io/${{ github.repository_owner }}/eshop-lite/api-gateway:${{ github.sha }}
        env:
          FLY_API_TOKEN: ${{ secrets.FLY_API_TOKEN }}
      - name: Staging smoke
        run: curl -f https://eshop-lite.fly.dev/actuator/health
```

Required GitHub Actions secrets:
- `GITHUB_TOKEN` (automatic)
- `FLY_API_TOKEN`
- `JWT_SECRET`
- `DB_URL_USERS`, `DB_URL_CATALOG`, etc.

### 4) Data/Security/Observability/NFR
- Secrets must never appear in logs (GitHub Actions masks automatically).
- Use separate Fly.io apps per service or a single gateway-only deploy in free tier.
- NFR: full deploy pipeline completes within 10 minutes.

### 5) Tech Lead Guidance
- Add `fly.toml` per service under `infra/fly/`.
- Use Fly.io managed Postgres for staging DB if local DB is not tunnelled.
- Add pipeline status badge to `README.md`.
- Define re-deploy strategy: rolling update preferred.

### 6) QA Matrix
- **US24-P1** pipeline completes on clean main push (`TC-S5-CD-01`).
- **US24-P2** secrets masked in logs (`TC-S5-CD-02`).
- **US24-P3** re-run is idempotent (`TC-S5-CD-03`).
- **US24-N1** staging smoke failure blocks pipeline.

### 7) Fly.io Config Snippet (`fly.toml`)
```toml

[build]

[env]
  SERVER_PORT = "8080"
  SPRING_PROFILES_ACTIVE = "k8s"

[http_service]
  internal_port = 8080
  force_https = true
```
